# Conformance and support

This project implements selected software-verifiable requirements from STANAG
4607 Edition 4 / AEDP-4607 Edition A Version 1. It is not NATO-certified, and
support for a structure does not establish operational conformance of a producer
or an entire stream.

| Area | Status | Evidence |
|---|---|---|
| Packet header P1-P10 | Implemented | Exact 32-byte structural decode and encode, size bounds, big-endian integers, reserved-value preservation, and independent synthetic header bytes in `tests/test_packet_header.py` |
| BCS character validation | Implemented for typed contemporary fields | P1/P3/P5/P8, M1/M2/M4, J3, F1-F3, and C2/C3/C6.2/C6.3 are checked against the Annex A repertoire without changing received bytes |
| Complete packet framing | Implemented | Exact declared-size checks, configurable packet and segment-count bounds, malformed/truncated rejection, and byte-identical round trips in `tests/test_packet_framing.py` |
| Segment header | Implemented | Exact 5-byte structural decode and encode with big-endian S2 and minimum-size enforcement |
| Unsupported segment preservation | Implemented | All segment types, including reserved values and registered extension IDs 128-132 whose layouts are absent from Annex L, are exposed as opaque payload bytes and re-encoded losslessly |
| Mission Segment M1-M7 | Implemented | Exact fixed-width decode/encode, reference-date ranges, unknown platform enumeration preservation, and independent Edition 4 fixture bytes in `tests/test_mission.py` |
| BA16/BA32 and SA16/SA32 angles | Implemented | Exact raw integer preservation, rational-degree conversion, big-endian round trips, and both Annex C worked examples in `tests/test_angles.py` |
| B16/B32 and signed-Hertz H32 decimals | Implemented | Exact sign-magnitude preservation, rational conversion, big-endian round trips, maximum magnitudes, and negative zero are covered in `tests/test_binary_decimals.py` |
| Dwell Existence Mask D1 | Implemented | Exact 64-bit mapping for D2-D31 and D32.1-D32.18, mandatory-field audit, spare-bit preservation, and deterministic field widths in `tests/test_dwell_mask.py` |
| Dwell Segment fields D1-D31 | Implemented | All selected fields are framed at exact Table 3-9 widths; every value has a typed, unit-explicit accessor; optional absence remains explicit; all field bytes round-trip |
| Target Report fields D32.1-D32.18 | Implemented | Repeated count-bounded reports are framed at exact Table 3-10 widths; all values have typed, unit-explicit accessors; direct and reduced target locations use exact binary-angle arithmetic; absence remains distinct from zero; every field remains exactly accessible and round-trippable |
| Dwell/Target conditional semantic validation | Implemented for software-verifiable field rules | Mandatory mask bits, D4 flag, count, length, zero-target mask exception, coordinate representation, Dwell presence groups, target-uncertainty preconditions, radial/wrap velocity pairing, truth-tag pairing, spare bits, and mechanically verifiable Table 3-9/3-10 ranges are checked |
| HRR Existence Mask H1 | Implemented | Exact 40-bit Figure 3-4 mapping for H2-H31 and H32.1-H32.4, mandatory-field audit, spare-bit preservation, and deterministic fixed-header width are covered in `tests/test_hrr_mask.py` |
| HRR fixed metadata H2-H31 | Implemented | Every mask-selected fixed field is losslessly framed, exposed with exact unit-aware numeric accessors, dispatched as `HrrSegment`, and exercised by the pinned public synthetic two-segment sample |
| HRR fixed-metadata validation | Implemented for software-verifiable field rules | Mandatory/conditional presence by H23, H6/H7 count presence, H25/H26 declarations, H32 phase/index mask relationships, numeric ranges, flags, enumerations, and spare bits are reported non-destructively |
| HRR Scatterer Records H32 | Implemented for uncompressed records; compressed preservation only | H25/H26-sized magnitude and optional phase plus H1-selected two-byte range/Doppler indices decode as exact `HrrScattererRecord` values; malformed record widths and sparse H7 totals are validated, while all H32 bytes still round-trip exactly. H16=1 threshold-decomposition remains bounded and opaque because its decompression wire algorithm is not sufficiently specified |
| Job Definition J1-J28 | Implemented | Exact 68-byte decode/encode, typed bounding area, radar/task/model context, exact No Statement preservation, semantic nominal-value accessors, and independent public Edition 4 fixture evidence in `tests/test_job_definition.py` |
| Job Definition validation | Partial | J1, J4, J5, J16-J19, J23, and J25 mechanical ranges and reserved bits are reported non-destructively; spherical convexity remains planned, while P10 Job ID context is checked separately |
| Free Text F1-F3 | Implemented | Variable-length type-6 decode/encode preserves the exact originator, recipient, and message bytes; payload bounds, Annex A BCS characters, and all-space fields are validated in `tests/test_free_text.py` |
| Processing History C1-C6 | Implemented | Count-bounded type-12 decode/encode preserves original and modifying system identities, ordered processing records, and all C6.6 processing flags exactly; independent structural vectors and malformed sizes are covered in `tests/test_processing_history.py` |
| Processing History validation | Implemented for software-verifiable field rules | Nonzero source/modifier Job IDs, sequential C6.1 values, and reserved C6.6 bits are reported without altering provenance records |
| Platform Location L1-L7 | Implemented | Exact 23-byte type-13 decode/encode exposes time, SA32/BA32 position, WGS 84 ellipsoid altitude, track, speed, and vertical velocity; synthetic structural evidence is in `tests/test_platform_location.py` |
| Platform Location validation | Implemented | L1 time, L4 altitude, and L6 speed ranges not guaranteed by their wire types are reported non-destructively |
| Test and Status T1-T6 | Implemented | Exact 14-byte type-10 decode/encode, named T5 hardware failures, named T6 operational-limit failures, UTC context from T4, time validation, and reserved-bit diagnostics are covered in `tests/test_test_status.py` and `tests/test_context_stream.py` |
| Job Request R1-R26 (101) | Implemented recommended segment | Exact 79-byte decode/encode preserves request identity, priority, SA32/BA32 area, radar requirements, UTC start components including leap-second representation, timing, sensor identity, and initial/cancel flag; ordinary dates expose timezone-aware UTC values, while BCS, calendar validity, and software-verifiable Table 4-1 ranges are validated against independent derived bytes |
| Job Acknowledge A1-A25 (102) | Implemented recommended segment | Exact 79-byte decode/encode preserves assigned Job ID, correlated request identity, sensor/task parameters, area, status, UTC start components including leap-second representation, and nationality; ordinary dates expose timezone-aware UTC values, while BCS, calendar validity, and software-verifiable Table 4-2 ranges are validated against independent derived bytes |
| Incremental/live packet parsing | Implemented | Arbitrary chunks, bounded partial-packet buffering, explicit terminal truncation, fail-closed state, and reset behavior in `tests/test_stream.py` |
| Stream resynchronization after corruption | Not implemented | A malformed packet fails closed; the caller must reset at a known boundary |
| Validation and reporting | Implemented for the documented profile | Stable structured issues cover packet/header context and every typed segment without rejecting or mutating preserved wire values; the CLI aggregates them with conservative Dwell/HRR continuity checks and bounded issue retention |
| Packet Job ID context | Implemented | `validate_packet_context()` defaults to the Edition A P10 zero/nonzero relationship from section 3.1.10. An explicit narrow compatibility profile accepts the observed Version 3.0 Job Definition-only convention only when J1 equals P10; it does not alter packet bytes or claim Edition 3 conformance |
| Typed application events | Implemented | `iter_packet_events()` yields supported typed values in wire order while retaining the exact source `Segment`, `PacketHeader`, and segment index; unsupported values remain opaque |
| Contextual live events | Implemented | `ContextualStreamDecoder` processes arbitrary chunks, retains bounded LRU Mission/Job state by exact platform and mission/job IDs, resolves D6/T4/L1 to UTC only when a valid M5-M7 date is known, reports invalid or unrepresentable time arithmetic without raising or inventing time, and emits explicit new/repeat/replace updates plus deterministic eviction keys |
| Dwell/HRR stream continuity | Implemented conservative profile | A bounded `StreamContinuityValidator` keeps independent type-2/type-3 state per exact job and reports same-revisit D3/H3 gaps, data after D4/H4=1, and nonzero first-dwell indexes at an observed revisit transition without guessing whether a revisit reset is legitimate |
| GeoJSON target export | Implemented application adapter | `dwell_to_geojson()` exports complete direct or reconstructed target locations with normalized longitude, observation metadata, and exact raw-coordinate provenance; no GIS dependency is required |
| Inspect/validate/GeoJSON CLI | Implemented application adapter | The `stanag4607` command processes files or standard input incrementally and exposes supported segment summaries, structured validation with configurable bounded issue retention, and streaming GeoJSON output |
| Local replay demo | Implemented application adapter | A localhost-only-by-default, dependency-free UI replays a file through the real incremental decoder and validators, bounds its browser timeline/activity history, and plots complete target positions without adding fusion semantics |
| Public synthetic interoperability corpus | Implemented as non-normative evidence | Eight unchanged Apache-2.0 Edition 4 packets cover core fields, practical optional segments, context replacement, opaque reserved/extensions, and HRR framing with exact hashes and a pinned upstream revision |
